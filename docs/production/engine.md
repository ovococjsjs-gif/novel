# Движок и формат сценария

## 1. Файлы

| Файл | Что делает |
|---|---|
| `index.html` | Разметка, порядок подключения скриптов. **Порядок глав по умолчанию = порядок `<script>`** |
| `vn-config.js` | Персонажи, спрайты и эмоции, говорящие, допустимые `weather` / `camera` / `effect`. Общий для движка и валидатора |
| `vn-core.js` | Парсер условий и компилятор глав в плоский список инструкций. Общий для движка и валидатора |
| `script/_registry.js` | **Реестр переменных** (`VN_VARS`) и пороги концовок (`VN_THRESHOLDS`) |
| `script/<chapter_id>.js` | Главы. Имя файла = `id` главы |
| `engine.js` | Сцена, исполнение, сохранения, меню, dev-режим |
| `tools/validate.js` | Проверка сценария: `node tools/validate.js` |

## 2. Глава

```js
window.VN_CHAPTERS = window.VN_CHAPTERS || [];
window.VN_CHAPTERS.push({
  id: "day2_2_zero",                       // = имя файла
  day: "ДЕНЬ 2 · ОСТАЛОСЬ 20 ДНЕЙ",        // метка в HUD
  title: "Квартира ноль",
  subtitle: "Старокупеческий переулок · 14:10",
  bg: "bg_summer_town_day",                // короткое имя или полный путь
  bgm: "workflow.mp3",
  weather: "none",
  next: "day2_3_walk",                     // необязательно, см. ниже
  nodes: [ /* узлы */ ]
});
```

`next` — куда идти после последнего узла:
- не указан → следующая глава по порядку в `index.html`;
- строка → id главы;
- массив правил → первое подходящее: `[{ if: "route == 1", to: "w2_mirael_1" }, { to: "w2_lena_1" }]`;
- если некуда — экран «Продолжение следует».

## 3. Узлы

Состояние сцены (фон, музыка, погода, камера, спрайты) **сохраняется**, пока его не сменят.

| Поле | Значение |
|---|---|
| `speaker` | Имя из `vn-config.js` → `SPEAKERS`. По умолчанию «Рассказчик» |
| `text` | Текст. Реплики получают «— » автоматически, мысли — «…» |
| `thought: true` | Внутренняя речь |
| `sprite` | `"clear"` · `{char, emotion, pos}` · `{left:{…}, right:{…}}` · `{center:{…}}`. `pos`: left / center / right |
| `bg`, `bgm`, `weather`, `camera`, `effect` | Смена окружения. `camera`: none / ride / shake; `effect`: flash |
| `label: "имя"` | Метка — сюда можно прыгнуть |
| `jump: "цель"` | Переход **после** узла: `"метка"` в этой главе, `"chapter_id"`, `"chapter_id#метка"` |
| `set: {flag: true}` | Присвоить переменные (до показа текста) |
| `effects: {aff_lena: 1}` | Прибавить к переменным |
| `if` / `then` / `else` | Условный блок: `{ if: "lena_told_truth", then: [ … ], else: [ … ] }`. Узел с `if` ничего больше не делает |
| `choice` | Выбор, см. §4 |
| `ending: {id, title, text}` | Концовка: экран финала, запись в мета-прогресс |
| `note` | Комментарий автора, игрой не показывается |
| `lint_ok` | Код или массив кодов ложных стилевых предупреждений валидатора для этого узла (§10). Игрой не используется |

Узел без `text`, но с `bg`/`sprite`/… — тихая смена сцены без остановки.

## 4. Выбор

```js
{ choice: { id: "d2_lena_truth", prompt: "Лена смотрит на ссадину.", options: [
  { label: "Сказать, что чуть не сбили", effects: { aff_lena: 1, inner_sight: 1 }, set: { lena_told_truth: true },
    next: [ { speaker: "Лена", text: "…" } ] },
  { label: "Отшутиться про асфальт", effects: { inner_sight: -1 }, next: [ … ] },
  { label: "Спросить про Буфер", if: "glitch_1", jump: "buffer_talk" }
] } }
```

- `id` — уникален **на всю игру** (валидатор проверяет).
- `if` у варианта — вариант скрыт, если условие ложно.
- `next` — вложенные узлы ветки; после них игра продолжается **после выбора**. `jump` — уйти в метку/главу (можно вместе с `next`, тогда после ветки).
- Без `next` и `jump` — просто продолжить.
- Клавиши 1–9 выбирают вариант. «Назад» из выбора и через выбор работает (откатываются и переменные).

## 5. Условия

Строка: `"aff_mirael >= thr.good_aff && inner_sight >= thr.good_sight"`, `"glitch_count >= 3 and not route"`, `"meta.cleared_mirael_good"`.
Операторы: `== != >= <= > <`, `&& || !` (или `and or not`), скобки, числа, `true`/`false`.
Особые имена: `meta.<флаг>` — мета-прогресс между прохождениями (`meta.cleared_<id концовки>`), `thr.<имя>` — порог из `VN_THRESHOLDS`.
Объект: `{ all: [...] }`, `{ any: [...] }`, `{ not: … }`.

## 7. Маршруты, концовки и пороги

### Вход в маршрут (`day7_2_stairs`, п. 31)

Подсчёт делает `routeCalc` в `vn-core.js`. В условиях он доступен как `calc.*`:

| Имя | Что |
|---|---|
| `calc.top` | наибольшая из `aff_mirael` / `aff_valeria` / `aff_lena` / `aff_taya` |
| `calc.leader` | номер маршрута лидера (1–4); `0`, если `calc.top` ниже `route_min` |
| `calc.second` | номер маршрута второго места |
| `calc.tie` | `1`, если лидер опережает второго меньше чем на `route_margin` |
| `calc.true_ready` | `1`, если открыты все пять `meta.cleared_*_good` |
| `calc.tie_count` | сколько маршрутов в группе лидеров при ничьей (0 без ничьей) |
| `calc.tied_1` … `calc.tied_4` | `1`, если маршрут в группе лидеров: отстаёт от лидера меньше чем на `route_margin` (п. 114) |

При равенстве очков порядок — по номеру маршрута.

Порядок в `day7_2_stairs`:
1. `calc.true_ready` → Саша закрывает жёлтую дверь, `route = 6`.
2. Дверь под лестницей при `glitch_1 && glitch_2` и «Открыть дверь» → `route = 5`, сразу `secret_c1` (Рассказчик обрывается уже там).
3. `calc.leader == 0` → `route = 3`, `earth_passive`, Саша остаётся на лестнице.
4. `calc.tie` → меню `d7_route` из всех лидеров группы (`calc.tied_N`), их может быть от двух до четырёх.
5. Иначе — сам приходит к лидеру (метки `arr_mirael` / `arr_valeria` / `arr_lena` / `arr_taya`).

Дальше `next` главы по `route`: `mirael_d8_1`, `valeria_d8_1`, `earth_d8_1`, `taya_d8_1`, `secret_c1`, `true_d8_1`.

**Ещё не написанные главы** перечислены в `window.VN_PLANNED` (реестр). Валидатор на них даёт предупреждение, а игра показывает «Продолжение следует» с названием маршрута (`VN_ROUTE_NAMES`). Пустых глав-заглушек не заводим: они появились бы в «Эпизодах». Когда глава написана, убрать её id из `VN_PLANNED`.

**Главы маршрутов** подключаются в `index.html` после Недели 1. У последней главы каждого маршрута обязателен явный `next` (или `ending`), иначе игра уйдёт в первую главу следующего маршрута по порядку файлов.

**Сцены-отклики Дней 5–7:** в конце `day5_3_night`, `day6_3_taya`, `day7_1_voices` стоят крючки `if: "calc.leader == N"` с `note`. Сцену писать прямо в `then`.

### Пороги (`VN_THRESHOLDS`)

| Порог | Значение | Смысл |
|---|---|---|
| `route_margin` | 1 | Отрыв лидера, при котором меню на лестнице не нужно |
| `route_min` | 3 | Ниже — пассивный вход в Земной |
| `good_aff` | 14 | Симпатия героини маршрута к финалу для хорошей концовки |
| `good_sight` | 20 | `inner_sight` к финалу для хорошей концовки |
| `bad_sight` | 0 | Не выше — плохая концовка |

Пороги концовок предварительные: они сверяются **в конце маршрута**, по сумме всех 21 дня.

**Неделя 1 по факту (`node tools/simulate.js`, `tools/balance.js`, 02.11, после расширения Дней 3–7):**
- максимум, если всё время выбирать одну героиню: Мира 13, Валерия 13, Лена 12, Тая 12 (Ника 5);
- «чистое» прохождение одной героини даёт ей 12–13, остальным 0–1, `inner_sight` +9…+19;
- `inner_sight` за Неделю 1: от −31 до +46;
- случайный игрок (`node tools/simulate.js --runs 4000`): средние симпатии 5.3 / 5.5 / 5.5 / 5.3; маршруты Мира 20 %, Валерия 23 %, Земной 24–25 %, Тая 20 %, Секретная 12–13 %; ничья и меню на лестнице примерно в 25 % партий;
- стратегия «бегство» по-прежнему уводит в пассивный Земной, «первый вариант» — в Земной, «взгляд внутрь» — к Тае.

**Бюджет маршрута (Дни 8–21), чтобы пороги сошлись:**
- героине маршрута — не меньше 10 достижимых очков симпатии;
- `inner_sight` — около +12…+16 при честной игре;
- выборы на `−sight` должны реально тянуть к плохому финалу.

После написания каждого маршрута прогнать `tools/simulate.js` и `tools/balance.js` и поправить пороги.

### Концовки

- **Хорошая** маршрута X: `aff_X >= thr.good_aff && inner_sight >= thr.good_sight` плюс ключевые флаги маршрута (см. план маршрута). **Плохая:** `inner_sight <= thr.bad_sight` или флаги-счётчики (`m_hide >= 2`, `t_blanket >= 2`, `t_signed`). Иначе нейтральная.
- **Секретная:** по `b_signs` и `b_resist` (пороги подбираются при написании).
- **Истинная** открывается по `calc.true_ready`.
- `id` концовок: `<маршрут>_<good|neutral|bad>`, где маршрут — `mirael`, `valeria`, `earth`, `taya`, `secret`; у Истинной — `true_good` (и `true_draft` для «Ещё одного черновика», п. 86). Хорошая концовка ставит `meta.cleared_<маршрут>_good`.

## 8. Сохранения и мета

| Ключ `localStorage` | Что |
|---|---|
| `nsnn_autosave_v2` | Автосохранение — на каждой реплике и выборе |
| `nsnn_saves_v2` | 6 слотов |
| `nsnn_meta_v1` | Между прохождениями: открытые концовки, `cleared_*`, пройденные главы и переменные на входе в каждую |
| `nsnn_settings_v1` | Настройки |

Сохранение — это снимок: глава, номер инструкции, переменные, сцена, спрайты, последние 40 шагов истории и 150 строк журнала. Старые сохранения (`*_v1`) не загружаются: формат несовместим.

**Версии глав в сохранениях.** Позиция хранится как номер инструкции, поэтому в снимок пишутся ещё отпечаток главы (`chHash`, хеш её исходника) и переменные на входе в неё (`entry`). Если при загрузке отпечаток не совпал (глава переписана после сохранения), игра предупреждает и начинает эту главу заново с переменными на входе: решения прошлых глав сохраняются, решения внутри главы придётся принять ещё раз. У старых снимков без `chHash` поведение прежнее: открываются по номеру инструкции, возможно не в том месте главы.

- **Играть** — новое прохождение с нуля (спросит подтверждение, если есть автосохранение).
- **Продолжить** — автосохранение.
- **Эпизоды** — только уже пройденные главы. Глава запускается с переменными, которые были на входе в неё в последний раз.

## 9. Dev-режим

Открыть игру с `?dev=1`:
- все эпизоды открыты, у глав виден id;
- панель слева сверху: глава, номер инструкции, все переменные (изменённые — жёлтым), открытые концовки, кнопка сброса меты;
- под вариантами выбора видны эффекты и условия;
- в концовках и в «Продолжение следует» видна статистика;
- в консоли — предупреждения про неизвестные переменные, отсутствующие эмоции и битые переходы.

## 10. Валидатор

```
node tools/validate.js            # ошибки + предупреждения
node tools/validate.js --quiet    # только ошибки
node tools/validate.js --stats    # объём по главам и грубый счёт сравнений рассказчика (ориентир п. 111)
node tools/validate.js --strict   # предупреждения тоже валят проверку
node tools/validate.js day2_2_zero day2_3_walk   # только эти главы
```

Баланс и маршрутизация:

```
node tools/balance.js             # по главам: максимум/минимум aff_* и inner_sight
node tools/balance.js --list      # все выборы с эффектами
node tools/simulate.js            # прогон стратегий (по героиням, sight, flee, random) → какой маршрут
node tools/simulate.js --runs 4000       # N случайных партий (сбои тоже на выбор) → доли маршрутов и средние симпатии
node tools/simulate.js mirael --glitch    # с принятием сбоев → Секретная
node tools/simulate.js mirael --meta true # все хорошие финалы открыты → Истинная
```

В браузере те же шесть развилок Дня 7 проверяет `tools/e2e_day7.js` (puppeteer, инструкция в шапке файла).

**Ошибки** (игра сломается): нет файла фона, спрайта или музыки; неизвестный персонаж, говорящий, поле или переменная; битое условие, переход или `next`; повтор id главы или выбора; выбор меньше чем из двух вариантов.

**Предупреждения** (стиль и канон, `style_guide.md`):
- слова-маркеры, церковная лексика, не тот сезон, реальные места и бренды;
- если предупреждение ложное (проверено глазами), в узел можно поставить `lint_ok: "nxy"` или массив кодов (`nxy`, `season`, `brand`, `church`, `marker`, `stamp`, `simile`, `length`, `fp`). Движок это поле игнорирует, валидатор глушит только названные проверки этого узла. Сначала стоит попробовать переписать фразу;
- «не X, а Y», больше одного «словно/будто» на реплику, первое лицо у рассказчика;
- длина реплик и кнопок;
- нарушение правила ±1 для `inner_sight`, щедрые `aff_*`;
- число выборов вне нормы, повторы «а что?», прозвища Лены;
- Саша в куртке без дождя;
- эмоция спрайта, которой нет (показывается запасная).

Перед каждым коммитом глав: `node tools/validate.js` без ошибок.
